  <action>
    Add a new `GET /api/alerts/enriched` endpoint to `backend/src/routes/alerts.routes.ts`. This endpoint is AFTER `router.use(requireAuth)` so it is auth-protected.

    The endpoint must:
    1. Get userId from `req.user.id`
    2. Call `db.getAlerts(userId)` to fetch all alerts for the user
    3. For each alert that has a `product_url`, enrich it with live product data:
       a. Check cache first: `cacheGet('alert-enrich:' + product_url)` (1hr TTL)
       b. On cache miss: detect store from URL using a simple `detectStore()` function (check hostname for daraz/telemart/shophive), then call `scrapeProductDetail(url, store)`
       c. Cache the result: `cacheSet('alert-enrich:' + product_url, product, 3600)`
    4. Use `Promise.allSettled` for parallel enrichment (not sequential -- N alerts = N parallel fetches)
    5. For alerts without `product_url`, return them as-is with `product: null`
    6. For alerts where enrichment fails, return them as-is with `product: null`
    7. Return JSON: `{ alerts: enrichedAlerts }` where each enriched alert has the original alert fields (snakeToCamel) plus a `product` field containing `{ name, imageUrl, price, store }` (from ProductDetail) or null

    IMPORTANT imports needed:
    - `import { scrapeProductDetail } from '../services/scraper.service';`
    - `import { cacheGet, cacheSet } from '../services/cache.service';`

    The `detectStore` function should be defined locally in alerts.routes.ts:
    ```typescript
    function detectStore(url: string): string | null {
      const lower = url.toLowerCase();
      if (lower.includes('daraz')) return 'daraz';
      if (lower.includes('telemart')) return 'telemart';
      if (lower.includes('shophive')) return 'shophive';
      return null;
    }
    ```

    The existing `snakeToCamel` function and `ensureUserProfile` are already in alerts.routes.ts -- reuse them.

    Do NOT modify the price_alerts database table. Per CLAUDE.md design principle: product data lives in Redis cache only, never persisted to PostgreSQL.

    IMPORTANT: The route must be placed BEFORE the `/:id` route to avoid Express matching "enriched" as an `:id` param.
  </action>
